# 1  项目前置内容介绍

## 1.1 项目模块现状介绍

当前项目分为前处理模块、训练模块、推理模块、评估模块和QC模块。

其中QC仅在前处理模块、推理模块和评估模型模块中生效。

### 1.1.1 前处理模块现状

当前的前处理模块有以下功能（以当前项目中的具体情况为准）：

1. 格式转换，包括 msdata2mzml、wiff2mzml；
2. 离子天顶算法，利用算法读取 mzml，找到每个 XIC 中最高强度点对应的RT，并生成 feature.csv；
3. 利用信号搜索功能找候选峰

### 1.1.2 推理模块现状

当前推理模块共有四种模式：roi 模式、roi2inference 模式、pipeline 模式、massnova 模式；

1. roi模式：输入mzml、mzml对应的label.xlsx，输出roi图像；
2. roi2inference模式：输入roi图像的路径，进行推理，得到模型推理的原始结果；
3. pipeline模式：roi+roi2inference+后处理，后处理包括：SNR矩阵筛选、框修正和置信度阈值筛选。
    1. SNR矩阵
        
        推理得到模型原始输出后，计算峰的局部信噪比和XIC图全局信噪比，构成矩阵，筛掉假阳性，它的"矩阵"本质是一个 **2×2 四象限分类**（全局RMS SNR vs 局部RMS SNR，阈值 3.0）：
        
        |  | **局部RMS ≥ 3** | **局部RMS < 3** |
        | --- | --- | --- |
        | **全局RMS ≥ 3** | 保留 | 当前可疑剔除 |
        | **全局RMS < 3** | 多峰复核 | 纯噪声剔除 |
    2. 框修正
        
        **输入**：SNR矩阵筛选保留下来的行。
        
        **主峰区间修正（interval correction）**：以模型框为初值，从峰顶沿 XIC 向两侧走"单侧噪声阈值截停"（`roi_bottom_decile_mean` / stable tail / low percentile 等模式，支持边界后验 lookahead），并做两重宽度上限约束：**≤ 1.08×预测框宽**（`post_refine_width_max_expand_vs_pred`）且 **≤ 0.45×ROI 窗口**（`post_refine_width_max_frac_of_roi`）；同时防撞同伴框（不侵入相邻事件区间）。
        
        **次峰识别**：模型小框 / ROI 次峰判据（`has_secondary_peak_in_roi`）/ 谷分裂（valley split）/ 主框双峰劈裂 / 左右重检，输出 `small / small2 / small3` 列，参数如 RT 容差 0.25 min、次峰≥主峰动态比例 0.04。
        
    3. **置信度/SNR 门控**（gate，见 blank_label.md）：
        - `gate_ok_for_adjustment` = 主峰 `score ≥ post_min_confidence(0.99)` 且 `SNR ≥ post_min_snr(10)` 且次峰判据通过，判定精修结果可信；
        - 精修后**对修正后的区间重算框外 SNR → `main_snr`**（这就是你那张 SNR 表里 `main_snr_stage4` 的来源，注意它用的是"修正后"区间，而 `snr_outside_box_stage3` 用的是修正前框）；
        - 复核档（sample_mode）还会算复合/最终置信度：`main_conf_composite = 0.45·ai + 0.25·snr_norm + 0.20·rt_term + 0.10·skew_term`；最终置信度 = `ai × RT 非线性衰减 × SNR 因子 × 偏度加权`（见 _final_conf_from_figure），`final_conf_best = max(main, small)`；**最终置信度 < 0.90 → `need_manual_review=1`**（防线 5 人工复核清单）。

## 1.2 项目模块重构

将整个项目分为训练线、推理线和评估线，由前处理、训练、推理、后处理和评估五个模块组成。质量控制（Quality Control，QC）为各阶段共用的检查与记录机制，不单独承担模型预测。

| 管线 | 组成 | 最终目的 |
| --- | --- | --- |
| 训练线 | 前处理 → 训练 | 生成训练数据并得到模型权重 |
| 推理线 | 前处理 → 推理 → 后处理 | 输出可复核的峰边界、峰面积与质量状态 |
| 评估线 | 前处理 → 推理 → 评估 | 在统一标注和匹配规则下评价模型原始能力 |

训练期间的验证集指标属于训练模块的内部监控，不等于独立测试。后处理效果另设对照评估，不能混入模型原始指标。

### 1.2.1 前处理模块

1. **converter模式：格式转换。** 接收厂商原始文件，输出mzML。当前材料记载支持msdata和wiff转换；wiff需要配套的同名wiff.scan。raw转mzML按原笔记作为后续扩展，不记为已完成。转换结果除检查文件是否存在，还应检查能否解析、是否存在有效色谱数据。
2. **data模式：统一时序数据。** 读取转换得到或主动上传的mzML，提取提取离子色谱（Extracted Ion Chromatogram，XIC），输出统一JSON。该阶段只组织数据，不输出预测峰。
3. **ROI构建：供推理和训练复用。** 根据参考保留时间（Retention Time，RT）截取感兴趣区域（Region of Interest，ROI），保存图像、原始时序和像素—RT映射。用户原先通过`roi`调用这一功能的入口保留，底层数据构建逻辑归前处理复用。
4. **COCO构建：供训练使用。** 将ROI与人工峰边界映射为目标检测数据集。一个独立峰对应一个边界框（Bounding Box）；负样本保留图像，标注框数组为空。

**data模式的输入/输出JSON示例：**

```json
{
  "items": [
    {
      "uid": "sample01_glucose_qual",
      "name": "Glucose",
      "channel": "qual",
      "mzq1": 142.0,
      "mzq3": 99.0,
      "smooth_sigma": 0.8,
      "x": [1.0, 1.1, 1.2, 1.3, 1.4],
      "y": [100.0, 500.0, 800.0, 300.0, 100.0]
    }
  ]
}
```

以上仅示范结构，5个点不代表能通过生产QC。JSON不支持注释，因此字段说明放在下表，保证示例可以直接解析。

| 字段 | 类型 | 必需 | 含义与约束 |
| --- | --- | --- | --- |
| `items` | array | 是 | 本次输入的色谱通道列表 |
| `uid` | string | 是 | 当前任务内每条XIC的唯一标识；不能只用化合物名区分双通道 |
| `name` | string | 否 | 化合物原始名称 |
| `channel` | string | 是 | 原笔记使用`quant`/`qual`表示定量/定性；与现有C接口的transition字符串存在差异，见第6节 |
| `mzq1` / `mzq3` | number | 是 | 母离子/子离子的质荷比（Mass-to-charge Ratio，m/z） |
| `smooth_sigma` | number | 否 | 非负值覆盖全局高斯平滑参数；0表示不平滑；需明确sigma使用采样点单位 |
| `x` | number[] | 是 | RT数组，单位min；应严格递增 |
| `y` | number[] | 是 | 强度数组，与x等长；不得含非有限数值 |

**补充建议：** 批量任务增加`sample_id`和稳定的`compound_id`，供跨样本与跨通道QC分组；增加`expected_rt`或由外部feature表提供该值。仅凭原JSON的`uid/name`无法可靠支持所有跨样本关系。重复时间点、缺失值、空数组等应记录具体原因，不应静默修复。

### 1.2.2 推理模块

推理模块负责模型加载、ROI图像输入、峰概率与边界框输出。信噪比筛选、信号级分峰和边界精修归后处理模块。

1. **roi模式。** 增加`input_type`参数。`file`表示读取mzML及label/feature，按参考RT构建ROI后停止；`data`表示读取data模式JSON，再构建ROI后停止。此模式只涉及QC1、QC2，不加载模型。
2. **roi2inference模式。** 读取已有`xic_roi`目录，执行模型预测与QC3，输出原始预测。为保证评估线洁净，此模式不自动执行QC4、QC5或生成精修结果；这是对原笔记中“roi2inference包含QC3–QC5”的结构性调整建议。
3. **pipeline模式。** 作为推理线的组合入口，依次调用ROI构建、模型预测和后处理，覆盖QC1–QC5。`pipeline`是管线编排入口，不另写一套模型算法。
4. **massnova模式。** 保留整条XIC信号搜索及可选模型验证的能力。候选搜索属于前处理/信号算法，模型验证属于推理，边界与质量判定属于后处理。其无参考RT场景不能强行套用参考RT型QC1，详见第3节。

原始预测至少保留`uid`、`sample_id`、`roi_id`、`query_index`、像素框、映射后的`peak_start/peak_end`、模型分数`score_ai`和模型版本。以上新增字段为重构建议，旧字段映射应单独维护。

所有候选均应可追溯。部署阈值可以生成筛选视图，但多阈值评估需要保留阈值筛选前的候选；否则不能用一份0.99阈值结果评估0.5阈值下的召回。

### 1.2.3 训练模块

1. **数据集生成。** 接收mzML或统一时序数据、人工label及ROI配置，生成训练/验证图像、COCO标注、数据划分清单和数据统计报告。现有材料中的图像规范为400×300 JPEG、参考RT±1 min；重构后应配置化，并记录真实窗口范围。
2. **标签读取。** `peak_label=0`表示明确负样本；`peak_label=1`表示正样本，其每组有效`peak_start1-3/peak_end1-3`生成一个框。空单元格不能自动视为负样本；无效标签单独列入数据检查报告。
3. **训练/验证隔离。** 按样本分组划分，尽量避免同一化合物双通道、同一原始样本的重叠ROI或增强版本跨集合。留出测试集不得参与训练、阈值选择或模型选择。
4. **模型训练。** 支持QuanFormer基线与MRMPFormer训练/微调，保存配置、日志、最佳权重和末轮权重。混合精度（Automatic Mixed Precision，AMP）等加速开关写入配置。
5. **模型结构。** MRMPFormer使用ResNet-50骨干、1层Transformer编码器（Encoder）和3层解码器（Decoder）。第一层预测完整二维初始框；三层通过细粒度分布精化（Fine-grained Distribution Refinement，FDR）预测/更新左右边界分布；最终上下边界来自第一层，左右边界和最终峰概率来自第三层。
6. **FDR说明。** 第二、三层残差累加发生在Softmax前的logits上，不应重复累加坐标偏移。层间边界反馈、分类损失、定位损失、分布监督及其权重记录到训练配置，不能把不同实验版本的配置混写为一个固定方案。
7. **训练输出。** 至少包含数据版本、划分清单、随机种子、模型配置、训练曲线、COCO平均精度/召回（Average Precision/Recall，AP/AR）与权重文件。AP75对边界更敏感，但AP50与AP75之差不能直接当作分钟级边界误差。

按照原笔记，生产QC不作用于训练模块。COCO生成仍需做标签合法性与数据一致性检查，作为数据构建检查记录，不以生产QC静默删除训练中的低信噪比或困难样本。

### 1.2.4 后处理模块

接收模型原始预测、对应XIC、ROI映射与参数配置，顺序执行信噪比（Signal-to-noise Ratio，SNR）筛选、边界精修、次峰复核、精修后重算与面积积分。

1. **SNR筛选。** 保留原笔记的全局/局部RMS四象限逻辑；框外SNR门控作为另一项明确记录。四象限阈值3.0与框外SNR阈值10.0不是同一个参数，不能互相替代。
2. **边界精修。** 以模型框为初值，从峰顶向两侧寻找符合截停条件的位置。保留所用基线方法、停止原因、原边界和新边界。材料中的宽度约束为不超过预测宽度1.08倍，且不超过ROI宽度0.45倍；这些是历史参数，不能保证适合所有宽峰。
3. **次峰复核。** 复用模型小框、ROI次峰判据、谷分裂和左右重检等来源。保留来源字段，信号算法新增的峰不能标成模型原生检出，也不能随意赋予模型置信度。
4. **精修后重算。** 对修正后的区间重新计算峰顶、框外噪声、SNR和积分面积；修正前SNR与修正后SNR分列保存。
5. **置信度记录。** 区分`score_ai`、复合置信度、最终规则分数及`need_manual_review`。原笔记中0.99/10为精修门控、0.90为人工复核阈值，含义不同；规则复合分数未经校准不能直接解释成真实正确概率。
6. **面积积分。** 在原始RT与强度序列上按确定的区间计算，明确使用原始积分、线性基线扣除或外部基线。平滑用于定位时，不应无记录地切换为平滑后面积。分钟/秒换算及边界插值方式统一记录。
7. **多峰输出。** 内部推荐每峰一行的长表，保留`peak_index`；对外兼容原`main/small/small2/small3`宽表。多峰分别积分，分叉峰按同一事件的完整外边界积分。

### 1.2.5 评估模块

1. **默认输入。** 模型原始预测、人工真实标注（Ground Truth，GT）、数据划分与QC记录。模型原始评估不读取`prediction_refined`作为替代。
2. **匹配规则。** 在同一样本、同一通道及对应ROI内，先按置信度阈值筛选，再要求起点和终点的绝对RT误差均不超过容差。采用一对一匹配；建议先最大化有效匹配数，再最小化总边界误差，并固定平局处理规则。
3. **计数规则。** 成功匹配为真阳性（True Positive，TP）；剩余预测为假阳性（False Positive，FP）；剩余GT为假阴性（False Negative，FN）。一个位置错误的预测可能同时留下一个FP和一个FN，不能只笼统标记MISS。
4. **检测指标。** 精确率（Precision）=TP/(TP+FP)，召回率（Recall）=TP/(TP+FN)，F1=2TP/(2TP+FP+FN)。分母为0的情况须固定约定，并同时输出原始计数。
5. **边界/定量指标。** 在明确配对规则下报告起止边界绝对误差、面积比较与相对误差。区分线性拟合R²和相对恒等线的预测R²；高R²不能单独证明面积无偏。相对标准偏差（Relative Standard Deviation，RSD）只在可比较的重复进样间计算，不混入浓度梯度。
6. **特殊峰。** 按已有`tag`报告双峰、三峰、分叉、前延、拖尾、宽峰等子组的GT数和指标；允许多个tag时说明组间重叠，不能相加作为总峰数。分叉峰与多峰的定义必须绑定label版本。
7. **空白样。** 独立报告空白样FP数和每条XIC平均FP；不能只报告全体样本P/R/F1掩盖空白误检。
8. **QC影响。** 同时列出原始样本数、排除数、实际评估数及排除原因。QC后条件指标与全流程指标分开；全流程中有GT但被前置QC拦截的对象仍须体现为未检出或单列失败贡献，不能消失于统计分母。
9. **后处理对照。** 对同一批样本另报精修前后边界与面积变化，并标注结果阶段。历史多模型指标必须附带权重、数据版本、阈值、容差与是否参与训练，不能跨实验直接拼接。

# 2 三条管线的执行逻辑

## 2.1 训练线

1. 准备mzML/时序数据与label，完成字段和标签检查。
2. 固定训练、验证、测试的样本分组；先划分，再生成各组派生数据。
3. 构建ROI与COCO框，记录正负样本数、峰数、特殊峰分布及被排除原因。
4. 执行训练或微调，在验证集选择权重与参数。
5. 保存模型、配置和训练报告；独立测试交评估线执行。

## 2.2 推理线

1. 通过`input_type`确定文件输入或时序输入；文件格式需要时先转换。
2. 做数据结构检查，执行适用的QC1和QC2，保存ROI与映射。
3. 调用模型并保存原始候选，QC3生成阈值通过结果。
4. 后处理执行QC4、边界精修、次峰处理和QC5。
5. 完成积分，输出逐峰结果、跨样本汇总、SNR报告与人工复核清单。

## 2.3 评估线

1. 冻结测试数据、GT版本、ROI配置和待比较权重。
2. 准备同一套ROI，执行适用的QC1、QC2并保留排除清单。
3. 运行`roi2inference`，保存可用于阈值扫描的原始候选。
4. 在预定的置信度—RT容差组合下执行QC3筛选及一对一匹配。
5. 输出总体、特殊峰、空白样和定量指标；不执行QC4、QC5以修改原始模型预测。

# 3 质量控制规则

## 3.1 QC1：RT一致性（qc1_rt）

1. 在QC2与ROI生成前，结合mzML提取信号及label/feature参考RT，构建同一化合物的样本—通道RT记录。
2. 同一样本同一化合物的两个通道RT差大于0.5 min时不通过；原笔记未明确单通道剔除策略，建议两通道均暂停并提示人工复核。仅一个通道时将通道级检查记为`not_applicable`。
3. 跨样本同一化合物所有适用通道的RT极差大于0.5 min时触发复核；按原笔记计算组中位数，偏离中位数大于0.5 min者排除，其余保留。
4. **边界情况：** 两个RT相差0.8 min时，两者距中位数均为0.4 min，因此会“触发组异常但无人被排除”。按原规则记录组异常及人工复核，不擅自改成两者都排除；若需更严格策略，应另行确认。
5. **RT取值待确认：** 原笔记要求以mzML为准，但未定义选哪个峰顶。建议同时保存`expected_rt`与`observed_apex_rt`，在参考窗口内确定观测峰顶；多候选不直接用整条XIC最大峰替代目标峰。
6. 不同仪器/方法的样本不宜默认共用一组0.5 min判据。补充建议按实验批次和方法分组；缺少可比参考时记录检查不可用及原因。

## 3.2 QC2：输入有效性（qc2_roi）

1. 在通过QC1或QC1不适用的基础上检查XIC。传入平滑参数则进行高斯平滑，否则不平滑；记录平滑参数与原始数组。
2. 按原笔记，拒绝条件是：**整条XIC最高强度小于1500，并且整条XIC点数小于20。** 两个条件用AND连接，不擅自改成OR。等于1500或等于20不触发相应严格小于条件。
3. 该规则意味着“强度很高但点数少”或“点数多但强度低”仍可能通过。建议分别记录`low_intensity`、`few_points`警示，是否升级为单项拒绝另行确认。
4. 空数组、x/y长度不一致、非有限数值、时间顺序非法属于数据结构错误，应在本规则之前拦截；不能借助AND条件让无效输入进入模型。
5. 全XIC点数与ROI点数分别记录，避免整谱点数充分但目标窗口无点。ROI完全无有效数据时不可生成可用推理图像。
6. 输出改为`qc2_roi_<样本>.csv`与汇总`qc2_roi.csv`，修正原笔记误写到`qc1_rt.csv`的问题。

## 3.3 QC3：模型预测阈值（qc3_threshold）

1. 记录每个ROI原始query数、模型峰概率、通过数、丢弃数和阈值。
2. 多峰检测保留所有符合条件的候选，不在原始层强制“每通道只留面积最大框”；该旧逻辑会破坏双峰/三峰召回。
3. 如最终业务确实只需一个主峰，在后处理另出主峰视图，并保留原始多峰明细。
4. 评估阈值由评估协议指定，部署阈值由模型验证结果确定。历史0.99与0.5阈值不能混为同一默认。

## 3.4 QC4：信噪比检查（qc4_snr）

| 条件 | 局部RMS SNR ≥ 3 | 局部RMS SNR < 3 |
| --- | --- | --- |
| 全局RMS SNR ≥ 3 | 保留至下一判据 | 可疑剔除，并保留原因 |
| 全局RMS SNR < 3 | 转多峰复核，不直接视为通过 | 纯噪声剔除 |

1. 另行记录框外噪声RMS、框外点数、框外SNR及其通过状态；材料历史默认框外SNR阈值为10、最少噪声点为5。
2. 明确SNR的信号分子是否扣基线，以及全局、局部、框外噪声各自取点范围。原笔记未提供完整公式，不能编造为已实现细节。
3. 框外含相邻真实峰时，噪声估计可能偏高；补充建议记录相邻峰掩码与有效噪声点数，避免真实次峰被算成噪声。
4. 噪声点不足或噪声估计为零时记录不可估计状态与处理原因，不直接当作高质量峰。

## 3.5 QC5：精修结果复核（qc5_refined）

1. 检查修正后起点小于终点、边界位于有效窗口、区间内存在足够数据，并记录左右扩张幅度和同伴框冲突。
2. 保存`main_refine_applied`及拒绝原因；精修未通过不等于原始模型无峰，应分别保留原框和精修状态。
3. 对主峰和各次峰分别记录原始模型分数、精修后SNR、来源、质量状态和面积。
4. 保留原笔记最终分数低于0.90进入人工复核的规则。`final_conf_best=max(main,small)`只用于兼容汇总；逐峰仍独立判断，避免高分次峰掩盖低质量主峰。
5. 原笔记“控制框线两边强度差异”补充为：记录左右端点强度差及相对峰高的差异比例。先作为诊断字段；拖尾峰和倾斜基线不一定左右等高，暂不设未提供依据的硬阈值。

## 3.6 模式与QC对应

以下为使三条管线职责一致的重构建议。

| 入口 | QC1 | QC2 | QC3 | QC4 | QC5 |
| --- | --- | --- | --- | --- | --- |
| roi | 适用时执行 | 执行 | 不执行 | 不执行 | 不执行 |
| roi2inference | 读取已有记录 | 读取已有记录 | 执行 | 不执行 | 不执行 |
| pipeline | 适用时执行 | 执行 | 执行 | 执行 | 执行 |
| 评估线 | 记录及披露 | 记录及披露 | 按评估阈值 | 不筛改原始预测 | 不筛改原始预测 |
| massnova | 有可比RT时执行 | 执行 | 使用模型时执行 | 按信号/模型分支记录 | 按实际精修分支记录 |

每一轮QC均输出阶段性汇总与分样本明细。没有执行的检查写`not_run`或`not_applicable`，不能伪装为通过；已有ROI续跑时应验证配置与来源版本。

# 5 对外接口与结果状态

## 5.1 输出JSON

原笔记位于data模式下的`task_id/status/peaks`实际上是推理结果，应移至本节。下例仅修正原示例语法及结构，不承诺现有接口已采用这些顶层状态。

```json
{
  "task_id": 1,
  "status": "success",
  "items": [
    {
      "uid": "sample01_glucose_qual",
      "peaks": [
        {"a": 1.15, "b": 1.45, "c": 0.995},
        {"a": 2.15, "b": 2.45, "c": 0.895}
      ]
    }
  ],
  "elapsed_seconds": 0.04
}
```

| 字段 | 说明 |
| --- | --- |
| `task_id` | 任务标识 |
| 顶层`status` | 任务执行状态；不代表每条XIC都通过QC |
| `items[].uid` | 回连输入的唯一标识 |
| `peaks[].a` / `b` | 峰起点/终点，单位min；此处为整理采用的解释，正式接口需核对头文件/实现 |
| `peaks[].c` | 峰分数；需确认是原始模型概率还是后处理分数，不混用 |
| `elapsed_seconds` | 任务耗时，单位秒 |

该输出示例独立展示接口形式，不与前面的5点输入构成可运行配对。建议新版本采用`rt_start/rt_end/score_ai`等明确名称，并兼容保留`a/b/c`。

## 5.2 通道级状态

PROJECT_FULL.md记载C++结果已有`uid + status + peaks + alerts`；应保留其语义，不能用统一空数组掩盖QC拒绝和无峰的差别。

| 材料记载状态 | 含义 |
| --- | --- |
| `ok` | 接受模型峰 |
| `review` + `SIGNAL_FALLBACK` | 无可用模型框，返回信号回退供审阅 |
| `alert` + `CHANNEL_LOW_INTENSITY` | 信号QC拒绝，具体原因以alerts为准 |
| `alert` + `NO_PEAK_FOUND` | QC通过但模型和回退均无峰 |

建议再区分输入错误与处理失败，采用版本化契约（Versioned Contract）。兼容旧接口时不能未经迁移就改变状态枚举。

## 5.3 Python与C++一致性

材料记载C++ ONNX输入为原始RGB `[0,255]`图像和`img_size=(W,H)`，归一化在ONNX内部完成；不得重复归一化。核对同一权重、图像渲染、像素到RT映射、平滑、阈值和积分设置，再比较两端输出。

现有C++信号QC为10点/1000强度，原笔记的新目标为20点/1500且AND连接。该差异需要显式迁移与版本标识，不能只修改文档就宣称两端一致。
