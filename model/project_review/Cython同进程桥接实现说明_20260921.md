# MRMPFormer / MassNova 同进程 Cython 桥接实现说明

## 目标与接口约束

后端继续使用现有 `qf_*` C ABI、`QfConfig`、`QfCompoundInput` 和结果 JSON。
DLL 初始化一次内置 CPython，导入编译后的 MassNova 模块并加载一次 ONNX；任务提交时 C
传入每个通道的 RT/强度数组，Python 完成整套峰识别，C 将最终 JSON 原样写盘并返回。

## ONNX 实际包含的逻辑

`mrmpformerv2.onnx` 当前只包含：

1. RGB 像素 `/255`；
2. ImageNet mean/std 标准化；
3. MRMPFormer 网络前向；
4. 二分类 softmax 后取峰类别分数；
5. 归一化 `cx,cy,w,h` 转像素 `x1,y1,x2,y2`。

ONNX 不包含候选峰枚举、0.5 阈值筛选、候选与框匹配、RT 边界精修、SNR/面积门控、
跨候选去重、信号峰评分、JSON 组装或 `status`。这些逻辑由共享 Python 核心执行。

## 单通道处理顺序

1. 校验 RT/强度数组，使用与 Python 推理相同的高斯平滑和通道 QC；
2. `SciPy find_peaks` 枚举最多 50 个候选，并执行峰高、prominence、最小间距、前沿区和浅谷合并规则；
3. 每个候选按峰顶切约 ±1 min 的 400×300 ROI；
4. 缓存的 ONNX Session 批量输出 query 分数与边界；
5. 使用严格的 `score > threshold`，再要求候选峰顶落在预测框内，贪心分配模型框；
6. 所有模型未命中候选分别执行边界精修、宽度保险、SNR/点数/面积门控；
7. 模型峰和信号峰一起按“明显重叠且无深谷”规则去重；
8. 在最终边界上统一重算面积、SNR、点数与峰分，按 RT 排序并返回全部峰。

## `status` 与 `c`

- 至少存在一个最终模型峰或通过门控的信号峰：`status="ok"`；
- 通道点数/最大强度 QC 失败：`status="alert"`，`CHANNEL_LOW_INTENSITY`；
- 候选枚举、模型和信号门控后均无峰：`status="alert"`，`NO_PEAK_FOUND`。

信号峰不再使用旧 C++ 的 `review + SIGNAL_FALLBACK`。它与模型峰一样进入 `peaks[]`：

- 模型峰 `c = model_score`；
- 信号峰 `c = signal_peak_score`，由 SNR 饱和分和有效峰点数分的加权几何平均得到，
  它是工程证据分，不是 softmax 概率。

## 代码位置

- 共享后处理：`model/inference/massnova.py::finalize_channel_peaks`
- 数组入口与最终 JSON：`model/inference/massnova_runtime.py`
- 缓存 ONNX Session：`model/inference/onnx_window_predictor.py`
- Python 生命周期门面：`model/inference/massnova_bridge.py`
- Cython 编译入口：`model/inference/massnova_bridge_native.pyx`
- C++ 嵌入层：`cpp/src/python_bridge.cpp`
- 任务透传：`cpp/src/task_manager.cpp`

## 发布内容

正式包需要 `mrmpformer.dll`、`mrmpformerv2.onnx`、私有 CPython 运行时、编译后的
MassNova `.pyd` 以及 NumPy/SciPy/Matplotlib/Pillow/ONNX Runtime 等运行依赖。客户机器无需
另装 Python。公开 C 接口没有变化，但发布包不再只是 DLL + ONNX Runtime + ONNX 三个文件。

## 当前验证边界

Python 单元测试已覆盖模型峰、多个信号峰、无峰、低强度 QC 和 ONNX 输入/阈值语义。
Python 单元测试 11 项通过；Cython 3.1.3 已完成四个扩展模块的 C 源码生成检查。项目现有
`.onnx_deps` 中的 ONNX Runtime 1.29.0 CPU Provider 已完成真实 `mrmpformerv2.onnx` 集成验证：
合成双峰输入返回两个峰、`status=ok`，模型加载约 0.66 s、单通道完整流程约 0.10 s；模块级
initialize/process/shutdown 生命周期也通过。当前机器仍缺少 C++/MSVC 工具链，因此尚未生成
可交付 DLL，也尚未执行 DLL 与 Python 的逐峰数值对比；正式发布前仍须在固定工具链环境完成
`.pyd`/DLL 编译、依赖收集、`test_api` 和同一批 RT/强度数组的 Python/C 对照。
