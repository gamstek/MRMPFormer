# C 接口与 Python MassNova 全流程一致性核验（2026-09-21）

## 结论

当前源码中的标准 Python MassNova 路径与 C DLL 内嵌路径，在收到同一条、以分钟为单位的
RT/强度数组之后，共用同一套 Python 候选枚举、ONNX 推理、模型框匹配、信号兜底、质量门控、
边界精修、去重和峰评分代码。标准部署阈值已统一为 `0.5`，判断条件为严格的
`model_score > 0.5`。

真实数据逐值对照结果：`test3_3.mzML` 前 64 个有效通道，共 133 个最终峰；两个入口返回的
左右边界 `a/b` 和峰分 `c` 最大绝对差均为 `0.0`，峰数、顺序和通道状态无差异。

这份结论目前属于“源码流程和 Python 运行时已验证一致”。本机没有 Microsoft Visual C++ 14+
工具链，因此尚未生成新的 `.pyd` 和 `mrmpformer.dll`，不能把尚未编译的新 DLL 宣称为已经完成
二进制端到端验收。Cython 已成功生成四个 C 源文件，编译停在缺少 MSVC，而不是算法或语法错误。

## 两条入口实际执行链

| 阶段 | 标准 Python MassNova | C 接口路径 | 是否同源 |
|---|---|---|---|
| 输入前端 | 从 mzML 读取 transition，排除 TIC/真重复通道，RT 转分钟 | 软件直接传一条 transition 的 RT/强度数组 | 输入形式不同（需求允许） |
| 通道 QC | 平滑后检查点数与最大强度 | `MassNovaArrayRuntime._prepare` 做相同检查 | 参数与判断一致 |
| 高斯平滑 | `gaussian_filter1d`，sigma=0.8 | 同一个 SciPy 函数，sigma=0.8 | 一致 |
| 候选枚举 | `massnova.enumerate_peaks` | 直接调用同一函数 | 同一实现 |
| 候选窗口 | `render_roi_jpeg`，峰顶附近 ±1 min | `validate_with_model` | 同一实现 |
| 神经网络 | `mrmpformerv2.onnx` + `OnnxWindowPredictor` | 同一 ONNX 文件、同一类、缓存 Session | 同一实现 |
| 阈值 | `score > 0.5` | `score > 0.5` | 一致 |
| 框与候选匹配 | 峰顶必须落框，按分数和中心距离贪心分配 | `validate_with_model` | 同一实现 |
| 未命中模型的峰 | 信号边界精修、宽度保险、SNR/点数/面积门控 | `finalize_channel_peaks` | 同一实现 |
| 去重 | 明显重叠、峰顶接近且中间无深谷才去重 | `finalize_channel_peaks` | 同一实现 |
| 峰分 `c` | 模型峰用 `model_score`；信号峰用可审计信号分 | `_finalize_peak_scores` | 同一实现 |
| 状态 | 峰明细写入 CSV/图 | 只要存在模型峰或合格信号峰即 `status="ok"` | 数值语义一致 |
| 返回载体 | CSV、图片、报告 | 既定 JSON 中的多组 `a/b/c` | 结构不同（需求允许） |

## C++ 层是否还有私有峰逻辑

正式 `mrmpformer` target 只编译：

1. `api.cpp`：参数校验和既定 C ABI；
2. `json_protocol.cpp`：输入解析；
3. `python_bridge.cpp`：初始化同进程 CPython、传入数组并取回 JSON；
4. `task_manager.cpp`：任务、超时、取消、回调和结果文件。

旧的 `onnx_inference.cpp`、`signal_processing.cpp`、`roi_renderer.cpp` 不再编入正式 DLL。
`task_manager.cpp` 不再修改峰、不再只取全局最高峰，也不再自行决定信号兜底状态；Python 最终 JSON
被原样保存并返回。旧信号处理文件仍供独立历史单元测试使用，不进入生产 target。

## 当前统一参数

- 模型：`checkpoint/mrmpformerv2.onnx`
- 模型峰阈值：`0.5`，严格大于才通过
- 平滑：`sigma=0.8`
- ONNX provider：默认 CPU（`use_gpu=-1`）
- batch size：128
- 通道最少点数：10
- 通道最小最大强度：1000
- 信号兜底：SNR 至少 10、峰区连续点至少 5
- 单通道候选上限：50
- 去重：峰顶容差 0.2 min、较窄区间重叠至少 25%、校正后谷底比例至少 0.70

全部 28 个扫描、边界、门控、去重和信号评分参数已比较；标准配置与嵌入运行时默认值一致。
测试 `test_deployment_config_matches_embedded_runtime_defaults` 会在今后参数只改一侧时直接失败。

`post_min_confidence=0.99` 是旧 pipeline 的二轮后处理参数，不参与当前 MassNova 整谱路径，不能与
当前模型峰阈值 `threshold=0.5` 混为一项。

## 输入契约

为了得到同一数值，软件传给 C 接口的数据必须满足：

1. 每个 item 是一条已经区分好的 MRM transition；
2. RT 单位必须是分钟，严格递增；
3. RT 与强度数组等长且均为有限数；
4. 如果 `QfCompoundInput.smooth_sigma=0`，使用全局默认 0.8；正数表示该通道明确覆盖全局平滑值；
5. C 和 Python 必须使用同一个 ONNX 文件、相同阈值及 provider。CPU 是当前标准部署基线。

Python 的 mzML 通道拆分、TIC 排除、重复通道排除和秒/分钟判断发生在输入前端。C 接口收到的是
软件已经拆好的数组，所以这些动作不会在 DLL 中重复。若软件传入秒而不是分钟，峰宽、窗口和 SNR
邻域都会改变，结果不会一致。
